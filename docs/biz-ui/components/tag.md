# Tag 구현 기록

`apps/biz-ui/src/components/Tag` 구현 기록입니다. 공통 개발 규칙은 [`apps/biz-ui/CLAUDE.md`](../../../apps/biz-ui/CLAUDE.md)를 따르고, 여기에는 이 컴포넌트 고유 사실만 둡니다.

Figma: [Tag 섹션](https://www.figma.com/design/IGi6n6Cz0bB54WWlhivIOH/-Design-system--BIZpartner?node-id=129-640&m=dev) (`129:640`). 실제 값은 심볼 하나(`115:497`)에서 실측했습니다.

## 구현 현황

| 컴포넌트 | 티켓       | 설명                                        |
| -------- | ---------- | ------------------------------------------- |
| `Tag`    | DOTOLI-257 | 단일 variant. 서브 컴포넌트 없음            |

## Variant 축

**축이 없습니다.** 섹션 안에 심볼이 `115:497` 하나뿐이고 variant 프로퍼티도 없습니다. 색·크기·`disabled` 모두 정의된 것이 없어 열지 않았습니다.

## 실측 스펙

심볼 77 × 30, 자식은 텍스트(`94:995`, x=12 · y=5 · 36 × 20)와 X 아이콘 인스턴스(`94:996`, x=52 · y=8.5 · 13 × 13) 둘뿐입니다.

| 항목    | 값                                                             |
| ------- | -------------------------------------------------------------- |
| 높이    | 30 → `h-[30px]` 고정 (아래 「높이를 고정합니다」)               |
| 폭      | **고정하지 않음.** 심볼 77은 `계정명` 기준 hug                  |
| padding | 좌우 12 → `px-[12px]`. 상하 5는 높이 고정으로 대체              |
| gap     | 4 → `gap-[4px]` (텍스트 끝 48 → 아이콘 시작 52)                 |
| radius  | 6 → `rounded-6`                                                 |
| 배경    | `blue/500` `#3182f6` → `bg-blue-500`                            |
| 라벨    | `label` (14 · Medium · 1.45 · -3%) → `text-label` · `text-white` |
| 아이콘  | `x` 13 → `text-[13px]`. **라벨 오른쪽**                         |

라벨 타이포는 Figma 변수 이름이 그대로 `label`이고 값도 `--text-label`(0.875rem · 1.45 · 500 · -0.03em)과 정확히 일치합니다. `Chip`이 쓰는 `label-semibold`와는 **웨이트만 다릅니다**(500 ↔ 600).

색은 두 토큰 다 흰색입니다 — 라벨이 `color/white/solid`, 아이콘이 `White`. 아이콘은 웹폰트라 `currentColor`를 타므로 버튼의 `text-white`를 그대로 물려받고, 따로 색 클래스를 두지 않았습니다.

### 아이콘 웨이트는 `bold`입니다

Figma 인셋을 역산해 `@phosphor-icons/core@2.1.1`의 실제 path 바운딩과 대조했습니다. 방식은 [chip.md](./chip.md) 「아이콘 웨이트는 `bold`입니다」와 같습니다.

13px 박스 · 인셋 `17.17% 17.18% 17.18% 17.18%` → 글리프 8.533 × 8.535 → viewBox 256 환산 **168.03 × 168.06**.

`x`는 획 두 개가 라운드 캡으로 끝나 바운딩이 「캡 중심 ± 캡 반지름」으로 딱 떨어집니다.

| 웨이트    | path 캡 중심 · 반지름          | viewBox 256 바운딩 | 이번 값과의 차이 |
| --------- | ------------------------------ | ------------------ | ---------------- |
| `regular` | (56,56) · (200,200) · r=8      | 160 × 160          | −8.03 · −8.06    |
| `bold`    | (56,56) · (200,200) · **r=12** | **168 × 168**      | **0.03 · 0.06**  |
| `fill`    | 라운드 사각형 (32..224)        | 192 × 192          | 모양 자체가 다름 |

`fill`은 `x-fill.svg`가 **네모 안의 x**라 애초에 후보가 아닙니다. `x-circle`처럼 감싸는 도형이 붙는 계열도 마찬가지입니다.

`ICON_DEFAULT_WEIGHT`가 이미 `bold`라 넘기지 않아도 결과는 같지만, `CHIP_ICON_WEIGHT` · `BOTTOM_TAB_ICON_WEIGHT` · `CHECKBOX_ICON_WEIGHT` 선례대로 `TAG_ICON_WEIGHT`로 명시했습니다. 기본값이 바뀌어도 실측 결과가 유지됩니다.

## 결정

- **태그 전체가 `<button>`입니다 — X만 누르는 구조가 아닙니다.** Figma에서 X는 **별도 심볼이 아니라 태그 안의 아이콘 인스턴스**이고, 13 × 13만 히트 영역으로 쓰면 모바일에서 너무 좁습니다. 전체를 버튼으로 두면 77 × 30이 그대로 히트 영역이 됩니다.

  [chip.md](./chip.md) 「internal-ui와 갈린 지점」이 **internal-ui `Chip`에 해당하는 것이 biz-ui `Tag`**라고 미리 지목해 뒀고, 그쪽도 `<button>` 하나입니다. 같은 모노레포의 자매 DS와 구조를 맞췄습니다.

- **`onClick`이 필수입니다.** X 없는 variant가 Figma에 없어 **제거 아이콘이 항상 렌더**됩니다. 선택 prop으로 두면 눌러도 아무 일이 없는 X가 화면에 남을 수 있습니다. `NavigationListItem`이 같은 형태(`Required<Pick<…, 'onClick'>>`)입니다.

  internal-ui `Chip`은 `onClick?`인데 그쪽은 `disabled`일 때 X를 빼는 축이 있어 다릅니다.

- **접근성 이름은 `` `${label} 제거` ``입니다.** 버튼 내용을 그대로 읽으면 「계정명」이라 **무엇을 하는 버튼인지가 빠집니다.** 문구는 internal-ui `Chip`과 같게 뒀고, 다른 표현이 필요하면 `aria-label`로 덮습니다.

  `Chip`이 `aria-label`을 안 연 것과 갈리는데, 그쪽은 라벨 텍스트 자체가 컨트롤의 이름이라 덧붙일 동사가 없습니다.

- **높이를 고정합니다 — `h-[30px]`, `py-[5px]` 없음.** 패딩으로 쌓으면 `5 + 20.3 + 5 = 30.3`이 나옵니다. 라벨 행높이가 `label`의 `1.45 × 14 = 20.3`인데 **Figma 텍스트 박스는 20**이라 0.3px이 남습니다. `Chip`(32) · `CtaButton` · `IconButton` · `BottomTab`과 같은 처리입니다.

- **태그는 찌그러지지 않습니다 — `shrink-0` + `whitespace-nowrap`.** 근거는 [chip.md](./chip.md) 「칩은 찌그러지지 않습니다」와 같습니다. 공백 없는 한글의 min-content가 한 글자라, 둘 다 없으면 좁은 컨테이너에서 라벨이 글자 단위로 쪼개집니다.

  **말줄임은 하지 않았습니다.** internal-ui `Chip`은 `truncate` + `title`인데, chip.md가 그 방식을 「디자인 확인 필요」로 올려 둔 상태입니다. **결론이 안 난 것을 태그에서 먼저 택하면 같은 DS 안에서 두 정책이 생깁니다.** 두 컴포넌트를 함께 정하는 쪽이 맞아 biz-ui `Chip`과 같게 뒀고, 아래 「디자인 확인 필요」에 올렸습니다.

- **히트 영역을 확장하지 않았습니다.** CLAUDE.md 「히트 영역 확장」이 **Figma 주석으로 지정된 대상만** 확장하라고 하고, Tag 섹션에는 주석이 없습니다. `Chip`의 4px은 별도 요청으로 들어간 것이라 근거가 다릅니다.

  전체가 버튼이라 30 × 77이 이미 히트 영역이지만 세로는 여전히 44에 못 미칩니다. 아래 「디자인 확인 필요」에 올렸습니다.

- **`ref`를 엽니다 — 버튼 계열과 맞췄습니다.** `CtaButton` · `IconButton` · `FloatingPill` · `Filter`가 전부 `RefAttributes<HTMLButtonElement>`를 열고 있고, 안 여는 것은 `NavigationListItem` 하나뿐입니다.

  필요도 실제로 있습니다 — **태그가 제거되면 그 버튼이 사라져 포커스가 `body`로 떨어집니다**(실측 확인). 다음 태그로 포커스를 옮기는 것은 태그 하나가 아니라 목록 전체를 아는 소비자 몫인데, 그러려면 각 태그에 닿을 손잡이가 있어야 합니다. 래퍼에 자기 `ref`를 걸고 `querySelectorAll`로 우회할 수도 있지만, 소비자가 판단할 것이 없는 네이티브 통로를 DS가 막을 이유가 없습니다 (「폼 컨트롤 공통」 5와 같은 성격).

- **그룹 컴포넌트를 두지 않았습니다.** internal-ui는 `ChipGroup`이 `<ul>` · `<li>`를 씌워 주는데 여기서는 소비자가 배치합니다. `Chip`이 같은 결정을 한 이유(그룹의 축이 되는 prop이 있는데 쓰는 곳이 없음)와는 다릅니다 — **Tag는 그룹에 올릴 축 자체가 없고**(`label` · `onClick` 둘 다 태그마다 다름), Figma에도 그룹 심볼이나 태그 사이 gap 정의가 없습니다.

  **대신 리스트 시맨틱이 빠집니다.** 보조기술에서 「목록, 항목 3개 중 1번째」 안내가 없어지고 태그가 그냥 버튼 3개로 읽힙니다. 소비자가 `<ul>` · `<li>`로 감싸면 되지만 매번 기억해야 하는 것이라, 실제 사용처의 gap이 확인되면 그때 그룹을 여는 것이 맞습니다. 아래 「디자인 확인 필요」의 사용처 항목과 같이 봅니다.

- **`stopPropagation`을 넣지 않았습니다.** internal-ui `Chip`은 클릭 가능한 `Select` 박스 안에 들어가서 필요했던 것이고, biz-ui에는 아직 그런 소비처가 없습니다. 미리 넣으면 이벤트를 조용히 삼키는 동작이 근거 없이 남습니다.

- **`type='button'`을 하드코딩했습니다.** 태그의 버튼은 항상 제거 동작이라 `submit`이 될 일이 없습니다. `IconButton`이 `type`을 여는 것과 갈리는데, 그쪽은 용도가 정해지지 않은 범용 버튼입니다.

- **`disabled`를 넣지 않습니다.** Figma에 축이 없어 스타일을 정의할 수 없습니다 (`Chip` · `ItemCheckbox`와 같은 판단).

- **`transition-colors`를 걸지 않았습니다.** CLAUDE.md 「폼 컨트롤 공통」 8은 **상태 전환이 있는 컴포넌트**의 규칙인데, Tag는 hover · pressed · selected 어느 것도 정의돼 있지 않아 전환할 색이 없습니다.

## API

| prop         | 필수 | 기본값             | 비고                                          |
| ------------ | ---- | ------------------ | --------------------------------------------- |
| `label`      | ✅   | —                  | 태그 텍스트. 접근성 이름도 여기서 나옴        |
| `onClick`    | ✅   | —                  | 태그 전체가 버튼. 제거 동작                   |
| `aria-label` |      | `` `${label} 제거` `` | 문구를 바꿀 때만                           |
| `className`  |      | —                  | `<button>`(태그 전체)에 적용                  |

`ref`는 `<button>`을 가리킵니다 — 제거 후 포커스를 옮길 때 씁니다.

## internal-ui와 갈린 지점

**대응하는 것은 internal-ui `Chip`입니다** ([chip.md](./chip.md)가 미리 지목해 둔 대로). 이름은 안 겹치고 역할이 겹칩니다.

|               | internal-ui `Chip`            | biz-ui `Tag`                  |
| ------------- | ----------------------------- | ----------------------------- |
| 엘리먼트      | `<button>` (누르면 제거)      | **같음**                      |
| 접근성 이름   | `` `${label} 제거` ``         | **같음**                      |
| 아이콘        | `x` 0.75rem                   | `x` 13px · `bold` 명시        |
| `onClick`     | 선택                          | **필수** (X를 뺄 축이 없어서) |
| `disabled`    | 있음 — X를 빼고 커서만 바꿈   | **없음** (Figma에 축 없음)    |
| 긴 라벨       | `truncate` + `title`          | **넘침** (biz-ui `Chip`과 통일) |
| 이벤트 전파   | `stopPropagation`             | **안 함** (소비처 없음)       |
| 높이 · radius | 1.5rem(24) · `rounded-in-full` | 30 · `rounded-6`             |
| 색            | `bg-in-primary-02` (연한 배경) | `bg-blue-500` (진한 배경 · 흰 글씨) |
| 그룹          | `ChipGroup`(`<ul>`)           | 없음 — 소비자가 배치          |

높이 · radius · 색이 다른 것은 **Figma 실측**이고, `onClick` · `disabled` · `truncate` · `stopPropagation` · `그룹`이 다른 것은 위 「결정」에 근거가 있습니다.

## Storybook

`apps/storybook/src/stories/biz-ui/Tag.stories.tsx`, `meta.title`은 `core/biz-ui/Tag`. 스토리 3종입니다.

- `Default` — 컨트롤 패널용. `onClick`은 `argTypes`의 `action`이라 Actions 패널에 찍힙니다
- `List` — 계정 태그 5개를 340px 폭에 `wrap`으로. **여러 줄 자동 줄바꿈**과 **누르면 목록에서 빠지는 것**을 함께 봅니다
- `LongLabel` — 컨테이너보다 넓은 태그가 **넘치는 것**을 그대로 보여줍니다 (위 「디자인 확인 필요」의 라벨 길이 항목)

**정적 목록 스토리를 따로 두지 않았습니다.** `Chip`(`Matrix`) · `SelectionItem` · `ToggleListItem`(`States`)은 정적 스토리가 **variant · 상태 조합**을 보여주는데 Tag는 축이 하나도 없어 담을 것이 없습니다. 같은 그림을 두 번 그리면서 한쪽만 X가 안 먹는 상태가 되므로 `List` 하나로 합쳤습니다. 이름을 `Removable`이 아니라 `List`로 둔 것은 X가 항상 있어 「제거 가능」이 변별점이 아니고, 자매 스토리도 동작이 아니라 사용처 이름(`AlarmList` · `MultipleSelect`)을 쓰기 때문입니다.
